# Релиз «Наш Хамон»

Состояние проекта и путь боевого запуска. Этот файл — часть репозитория: обновляется при каждом изменении релизного состояния. Секреты сюда не пишутся.

## Два артефакта

| Артефакт | Где живёт | Назначение | Статус |
|---|---|---|---|
| Демо-витрина | https://ssrjkk.github.io/our-jamon/ | показ заказчику и трафику до запуска магазина; заказы не отправляются (баннер «Демо-витрина») | 🟢 релиз-кандидат: все гейты зелёные |
| Движок магазина | `shop/` (Next.js 16) | боевой магазин: корзина, Т-Банк, 1С, админка, согласие 152-ФЗ | 🟡 код готов, ждёт хостинг и боевые ключи |

## Гейты качества (запускать перед каждым релизом)

```
cd shop
npm run typecheck        # типы
npm test                 # unit: контракт каталога, подпись Т-Банка, SQLite, деплой-гейты, арт карточек
npm run build            # сборка движка
npx playwright test      # e2e: обе витрины, 3 вьюпорта, axe, путь покупателя
```

Зелёный набор: typecheck, сборка с `SHOP_URL` и `verify-build`, unit 186/186, e2e 289/289 (74 skipped — вьюпортно-условные). Полный прогон e2e на разгруженной машине идёт ~29 мин; под параллельной нагрузкой он растягивается до ~48 мин и рвётся по таймаутам, поэтому перед релизом набор гоняют одним, без соседних браузеров и `node --test`.

Брендовые фото отдаются вариантами под измеренные слоты, а не полным исходником: пузырьку ленты нужен знак 180 px, кадру шторки — 400 px на десктопе и полный кадр на мобильной сетке, герою первого экрана — 700/1000 px (слот 458 px у движка и 544 у демо, максимум 1086 device-пикселя на всём ряду экранов). Главная из-за этого несёт 107 КБ растров вместо 996 КБ. Пересборка — `node scripts/brand-variants.mjs`: он кладёт варианты в оба корня (`shop/public/brand/` и корень Pages), потому что витрины обязаны совпадать и по весу. Гейты: `artifact-paths` (каждый кандидат `srcset` лежит в своём корне, ненулевой и не под `.dockerignore`, наборы двух витрин совпадают), `catalog-parity` (знак выведен из кадра кольца), `card-art` (закрытая шторка кадр не грузит).

## Путь боевого запуска

### Шаг 0. Что должно прийти от Виталия (блокеры)

1. **Хостинг**: аккаунт Vercel или VPS с Docker — выбор за заказчиком
2. **Реквизиты ИНН/ОГРНИП** — получены 16.11.2026 (ИП Маринов В., банк «Точка»): блок «Реквизиты продавца» заполнен в футере обеих витрин
3. **Боевые ключи Т-Банка**: терминал и пароль эквайринга (подключены к расчётному счёту)
4. **Доступ к 1С:УНФ**: URL выгрузки каталога и токен (или решение работать на вшитом прайсе 0711)
5. **Розничные цены**: прайс поставщика или наценка лавки (27 позиций сейчас «уточняются»)
6. **Порог бесплатной доставки** и допуск взвешивания (±15 г) — цифры в env одной правкой
7. Фото/видео: разрешение на фото поставщиков дано владельцем 16.11.2026; 15 позиций закрыты кадрами domhamona.ru (ноги по выдержкам, пакет нарезки 8 мес, соломка, хамонеры, нож) и подключены в обе витрины; 41 позиция ждёт архив по кодам nf-; макро-видео нарезки для первого экрана по-прежнему нужно

### Шаг 1. Переменные окружения

Полный список с комментариями — `shop/.env.example`. Минимальный боевой набор:

```
SHOP_URL=https://<домен>            # боевой адрес, из него собираются sitemap/robots/canonical; для оплаты нужен именно https
# SHOP_MODE не задавать или задать live: пустое значение — уже боевой режим
ADMIN_PASSWORD=<минимум 16 символов>  # без него админка выключена
TBANK_TERMINAL_KEY=<терминал>
TBANK_PASSWORD=<пароль эквайринга>
TBANK_TAXATION=<система налогообложения>  # как в договоре с банком
TBANK_VAT=<НДС>                           # как в договоре с банком
ONEC_API_URL=<адрес выгрузки 1С>    # необязательно: без него витрина на прайсе 0711
ONEC_TOKEN=<токен 1С>
FREE_DELIVERY_FROM=<порог, ₽>
DELIVERY_CDEK_RUB=<тариф> DELIVERY_YANDEX_RUB=<тариф> DELIVERY_DRIVEE_RUB=<тариф>
ORDERS_DB_PATH=/app/data/orders.sqlite  # путь внутри образа; том обязателен, иначе база в слое контейнера
```

Четыре ключа Т-Банка и https-адрес — все вместе: не хватает любого, и магазин принимает заказ, но платёжную ссылку не создаёт (`payment_not_configured`). Проверка живой кнопки — шаг 3, пункты 2–3.

Демо-защита: `SHOP_MODE=demo` превращает магазин в витрину с демо-оплатой. Забытая переменная не может случайно сделать боевой магазин демо — demo включается только явным словом.

### Шаг 2а. Деплой на Vercel

```
cd shop
npx vercel login
npx vercel --prod
# в Dashboard → Settings → Environment Variables внести набор из шага 1
# sqlite на serverless не живёт: выбрать VPS, либо внешний Postgres (интерфейс orders допускает замену)
```

### Шаг 2б. Деплой на VPS (Docker)

```
scp -r shop/ vps:/srv/nash-hamon
cd /srv/nash-hamon && docker build --build-arg SHOP_URL=https://<домен> -t nash-hamon .
docker run -d --name nash-hamon -p 3000:3000 \
  --env-file .env -v nash-hamon-data:/app/data nash-hamon
curl -s http://127.0.0.1:3000/api/health   # {"status":"ok","mode":"live",...}
```

`--build-arg SHOP_URL` обязателен: Next снимает robots и prerender-страницы во время сборки образа, и без адреса в образ ложится адрес демо — живая витрина начинает печатать canonical и `og:image` на GitHub Pages, а robots отправляет роботов читать демо-карту сайтов. Сборка это не пропустит: `node scripts/verify-build.mjs` сверяет собранные файлы и падает, если в них встретился демо-хост или адрес разошёлся с SHOP_URL.

Данные заказов — в томе `/app/data` (SQLite); бэкап — копия файла в кроне. Именованный том, а не каталог хоста, потому что контейнер работает под пользователем `node`: Docker переносит в именованный том владельца каталога из образа, а каталог хоста он создаёт от root, и база там не откроется — `/api/health` честно ответит 503, но первый заказ будет потерян. Если нужен именно каталог хоста, отдайте его тому же uid, под которым в контейнере живёт `node`.

Рядом с новой базой не кладут старый `orders.json`: при первом открытии базы он считается легаси-очередью и импортируется целиком, а импорт не чинит то, чего не понимает. Снятая с продажи позиция на развес из прежней демо-выгрузки поднимает `Legacy weight price cannot be restored` — база считается недоступной, `/api/health` отвечает 503, заказы не читаются. Файл при этом остаётся нетронутым: уберите его (или перенесите в нём ставку) и перезапустите контейнер.

### Шаг 2в. Без Docker (уже проверено)

`SHOP_URL=https://<домен> npm run build:standalone` собирает самодостаточный пакет в `.next/standalone`; запуск `PORT=3000 SHOP_MODE=live node server.js`. На этой машине проверено: сервер поднимается, `/api/health` отвечает `{"status":"ok"}`, витрины 200.

### Шаг 3. После запуска

1. `https://<домен>/api/health` — статус и режим
2. Пробный заказ: кусок → подтверждение веса в админке (`/admin`, пароль из `ADMIN_PASSWORD`) → ссылка Т-Банка → оплата → webhook `paid`
3. Пробный фасованный заказ: оплата сразу через Init Т-Банка
4. Сверить витрины: цены на Pages-демо и движке совпадают (гейт catalog-parity держит)
5. Снять баннер «Демо-витрина» и решить судьбу демо-страницы: noindex или редирект на боевой домен
6. Открыть `https://<домен>/robots.txt` и `curl -s https://<домен>/ | grep -o 'rel="canonical"[^>]*'` — везде должен быть боевой домен. Адрес демо в этих строках означает, что образ собран без `--build-arg SHOP_URL`.
7. Несуществующий артикул (`/product/nf-00099999`) отвечает `200` с текстом «Страница не найдена» и тегом `<meta name="robots" content="noindex">`: карточка собирается на запросе, ответ начинается до того, как отработает `notFound()`, и Next не может переписать уже отправленный статус. В индекс страница не попадает, настоящие 404 остаются у путей без маршрута. Менять статус ценой отказа от пререндера карточек не нужно
8. Посмотреть журнал контейнера (`docker logs nash-hamon`): он обязан быть без `Error:`. Строка вида «Каталог 1С не принят (…): Invalid catalog payload…» при пустом `ONEC_API_URL` — не авария, а штатный режим на прайсе 0711; она пишется один раз на смену источника, а не на каждый просмотр, и её же видно в `/api/health` (`catalog.origin`) и в предупреждении админки
9. Пройти покупательский путь браузером на бою: карточка → корзина → оформление → страница заказа. Без боевых ключей банк шаг оформления обязан кончаться надписью «Ссылка на оплату недоступна. Заказ сохранён» с кнопкой повтора, а не молчанием или ошибкой
10. Принимать работу только по https. Cookie-файлы боевого образа (`NODE_ENV=production`) помечены `Secure`, и на `http://<адрес>:3000` браузер их не сохраняет: вход в админку возвращается к полю пароля, а страница заказа держится лишь на токене из ссылки. Открыть `http://127.0.0.1:3000/api/health` для проверки сервера можно, но путь покупателя и `/admin` смотрят через домен с включённым TLS-прокси

## Откат

VPS: `docker stop nash-hamon && docker run ... <предыдущий образ>`. Vercel: Promotions → откат на предыдущий deployment. SQLite-данные при откате не трогаются томом.

## Границы текущего релиза

- Автосообщения в мессенджеры (Telegram/WhatsApp/SMS) и бронирование ПВЗ СДЭК не подключены: ссылка на оплату передаётся покупателю вручную из админки
- Личный кабинет — без пароля по ссылке заказа (токен в URL); бэкенд-токен хранится в заказе
- Куски и ноги — по среднему весу с подтверждением при связи (решение Виталия), целые ноги — фиксированная цена за штуку
